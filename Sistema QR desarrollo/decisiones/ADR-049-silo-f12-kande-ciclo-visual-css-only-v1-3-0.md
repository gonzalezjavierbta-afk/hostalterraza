#### ADR-049: Silo F12 "Kande" - Ciclo Visual CSS-Only v1.3.0 -> v1.9.0 con Contenido Temporalmente Fijado en CSS y Plan de Migracion a Datos (Kernel `.meta-line` + `content.meta` + i18n)

* **ID:** ADR-049 | **Fecha:** 22 de septiembre de 2026 | **Estado:** Aprobado y entregado (desplegado en `main`/Vercel; ciclo CSS-only cerrado). Working tree limpio y sincronizado (`HEAD == origin/main == e528464`). Este ADR es cierre documental (`@docs-keeper-free`): 0 cambios de codigo por este cierre; el unico archivo de codigo tocado por el ciclo fue `css/templates/fiesta/f12.css`.
* **Autor:** Documentation Specialist / `@docs-keeper-free` (el ciclo visual fue implementado por el equipo frontend `*-free`; este ADR registra el patron y verifica archivo por archivo, patron ADR-006).
* **Problema:** Tras la entrega inicial del silo f12 "Kande" (ADR-048, v1.0.0), la Direccion itero el diseno del hero/boleteria/meta/footer en SEIS versiones adicionales (v1.4.0 -> v1.9.0) **100% CSS sobre un unico archivo** (`css/templates/fiesta/f12.css`), sin tocar el kernel (`evento-app.html`), SQL ni `admin.html`. Para lograr el layout aprobado sin cambios de datos ni de kernel, varias cadenas visibles del evento (titulo "KANDE", subtitulo de la cinta, contenido de la meta en 2 lineas, texto del CTA "COMPRAR ENTRADAS", copyright del footer) quedaron **fijadas temporalmente en el CSS** (pseudoelementos `::before`/`::after` con `content:` y escapes unicode ASCII-safe), conservando el texto crudo del kernel intacto en el DOM. Este ADR documenta ese patron, su deuda y el plan de migracion a datos para que no se convierta en un silo "de un solo evento" ni en una fuente de drift.
* **Diagnostico verificado (contra el archivo real del repositorio, ADR-006 - prevalece el archivo):**

Baseline del ciclo: commit `5d3676c` (f12.css v1.3.0).
    2. **Commits del ciclo (todos en `main`, ya desplegados via Vercel), TODOS tocan UNICAMENTE `css/templates/fiesta/f12.css`:** `6960cc6` (v1.4.0+v1.5.0 - hero titulo/subtitulo + cinta "Klandestino Bar", boleteria solo taquilla, meta 2 lineas; +330/-65), `17f8cb4` (v1.6.0 - cinta vuelve a su posicion con subtitulo, quita banda "BOLETERIA", fondo amarillo en WhatsApp; +46/-22), **`a45174f` (commit de Direccion, "Update f12.css": cambia el asset `--f12-asset-flora`; 1/-1)**, `de790a0` (v1.7.0 - cinta mas cerca del titulo, hero mobile compacto con fondo 100svh e info dentro por overlay, badge org cyan, CTA mobile menor, `.boleto-trust` discreto; +96/-39), `f6f13ed` (v1.8.0 - mobile con menos hueco bajo el titulo y mas aire entre items, CTA "COMPRAR ENTRADAS" 100% CSS, cinta de vuelta al fondo mostaza; +58/-17), `e528464` (v1.9.0 = HEAD - mobile +35% de subida, `.boleto-trust` sin resalte, footer "Klandestino Bar" via CSS, ceja `#org-name-badge` con transparencia `rgba(47,224,208,0.68)` + `backdrop-filter: blur(4px)`; +58/-23).

    4. **Evidencia de la deuda de migracion a datos (kernel real `evento-app.html`, 1724 lineas):** el kernel YA soporta meta en 2 lineas data-driven **solo para el silo f9**: `config_landing.content.meta = { fecha:{l1,l2}, hora:{l1,l2}, lugar:{l1,l2} }` (L810-813); el gate es `const __esF9Meta = document.body.className && document.body.className.includes('tpl-f9')` (**L817**); los nodos `.meta-line` / `.meta-line--2` se crean en L825/L831 y en cualquier otro silo se ignora `two` (comentario H-2 L814-816). Es decir: **extender el gate `__esF9Meta` a `.tpl-f12` + cargar `content.meta` en el evento Kande** habilita el patron data-driven sin reescribir el kernel.
    5. **Evidencia de la deuda de copyright real (i18n):** `js/i18n.js` pinta `landing.copy_chongo` = "© 2026 Chongotronik. Todos los derechos reservados." (**L250**; tambien L620/L990 en otros idiomas). El CSS de f12 lo oculta VISUALMENTE y pinta "Klandestino Bar" por `::before`, pero los lectores de pantalla y el texto real del DOM siguen leyendo "Chongotronik". Fix real = i18n/dato, no CSS.
    6. **Evidencia de la deuda de assets (D4):** `--f12-asset-papel` = `url("")` (**vacio**, L81); los demas assets son URLs externas (`i.ibb.co`, `gstatic.com`) - NO estan en Supabase Storage `assets/templates/f12/` como esperaba el contrato de ADR-048 (TSK-046). El commit `a45174f` de Direccion reemplazo `--f12-asset-flora` por otra URL externa.
* **Decision (patron aprobado para este ciclo y regla de migracion):**
    1. **Ciclo CSS-only sobre un unico archivo:** las iteraciones visuales de un silo ya entregado se hacen SOLO en `css/templates/fiesta/f12.css`, con Escudo GOLD local (llaves balanceadas, ASCII-safety, Cero Borrado de IDs `#mod-*`), sin tocar kernel/SQL/admin. Este ciclo lo cumplio (los 6 commits tocan un solo archivo).
    2. **Contenido temporalmente fijado en CSS:** se acepta como **deuda explicita y acotada** fijar en el CSS cadenas del evento (titulo, subtitulo, meta, CTA, copyright) mediante pseudoelementos con `content:` y escapes unicode, SIEMPRE conservando el texto crudo del kernel intacto en el DOM (`font-size:0`/overlay, Cero Borrado). Es un puente visual, NO la solucion definitiva.
    3. **Plan de migracion a datos (deuda D1/D2/D3):** (a) extender el gate `__esF9Meta` de `evento-app.html` (~L817) para habilitar `.meta-line` tambien en `.tpl-f12` (idealmente generalizarlo a un set de silos con soporte); (b) cargar `config_landing.content.meta = {fecha:{l1,l2},hora:{l1,l2},lugar:{l1,l2}}` en el evento Kande (Supabase); (c) migrar "KANDE"/subtitulo/CTA y el copyright a datos (contenido del evento / i18n `landing.copy_chongo`), retirando entonces el contenido fijo del CSS de f12. **[Nota de resolucion 2026-10-01]** El apartado (c), en lo que toca al **copyright** (D2/TSK-052), quedo **RESUELTO con un alcance mayor**: ya no es un arreglo del footer de f12 sino un **footer dinamico de organizacion en todas las paginas publicas de evento** (`evento-app.html` L1868-1891), que toma el nombre real de la org del join existente `organizaciones(nombre, plan)` + `effOrgNombre` y lo pinta con nodos DOM reales y `textContent`; se agrego la key i18n `landing.copy_derechos` (es/fr/en), se retiro el `::before` de `content` del CSS de f12 (y las marcas `::after` de f9/f9b) y se elimino el badge freemium `.htz-powered`, de modo que el sello "Powered by Taquilla Directa" (enlace a `index.html`) aparece en TODOS los silos y TODOS los planes. Los apartados (a) meta y (b) `content.meta` de f12, y el resto de D3 (textos fijos del hero/CTA), siguen pendientes. Estado real del fix: COMMITEADO y pusheado (`52bbad0` + `c3d95c6`; HEAD == origin/main), QA APTO 0 bloqueantes.
* **Justificacion:** la Direccion necesitaba converger el diseno del landing Kande con velocidad y sin abrir frentes de kernel/SQL (que exigen ADR y QA de runtime). El CSS-only con contenido fijo permitio iterar v1.4.0 -> v1.9.0 en un solo archivo, desplegable y reversible, manteniendo Cero Borrado. El costo es una deuda de mantenimiento: el silo f12 hoy es "de un solo evento" (contenido fijo Kande); el plan de migracion la cierra reutilizando el patron f9 ya existente en el kernel.
* **Impacto:** **1 archivo de codigo** tocado en todo el ciclo: `css/templates/fiesta/f12.css` (v1.3.0 -> v1.9.0; 2423 lineas / 86600 bytes en HEAD). **0 cambios a `evento-app.html` (kernel), `admin.html`, SQL, endpoints o esquema.** Commits en `main` ya desplegados por Vercel. Impacto documental: este ADR-049 + tareas D1-D6 (TSK-051..TSK-056) en `TASKS.md`, hito -16 en `NEXT.md` y nota de estado del silo en `PROJECT.md`.
