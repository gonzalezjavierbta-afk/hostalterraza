# 🏆 REGLAS DE ORO DE AUDITORÍA (v127-MASTER)

Este documento representa el blindaje técnico y operativo innegociable del Sistema QR Hostal Terraza. Cualquier intervención por parte de una IA ejecutora debe ser validada contra estos 16 mandatos incondicionales bajo el framework AI-DOS v1.2.

---

## 🛡️ I. Protocolos de Desarrollo y Datos (Cimiento)

### 1. Mandato de Prioridad Estructural (Data-First)
Toda tarea se divide estrictamente en dos fases secuenciales:
* **FASE I (Cimiento):** Certificar mapeo de IDs del Contrato de Datos v107, inyección física de atributos `onclick` y flujo de datos Supabase.
* **FASE II (Estética):** Aplicar diseño Afterglow y Geist 900 solo tras un log TRACE positivo.

### 2. Protocolo de "Cero Borrado" e Integridad (STRICT)
Prohibido eliminar los IDs lógicos de inyección (#event-title, #db-lineup, #unified-frame, etc.). Incluso si un módulo no se usa, debe permanecer con `display: none` para no romper el orquestador. No se pueden eliminar etiquetas `<svg>` de iconos técnicos ni `<div>` indicadores.

### 3. Protocolo de Masa Crítica y Segmentos (v123-Legacy)
* **Contrato de Volumen:** Toda entrega debe incluir el conteo exacto de líneas. Si el volumen es inferior al baseline (~300 líneas para `evento3.html`), se debe justificar la consolidación.
* **Entrega por Segmentos:** Para archivos extensos, la entrega debe fraccionarse en bloques delimitados por: `// === INICIO SEGMENTO: [nombre] ===` y `// === FIN SEGMENTO: [nombre] ===`.

### 4. Escudo de Auditoría GOLD (Salud del Sistema)
El sistema debe emitir obligatoriamente estos latidos en consola para certificar la entrega:
* **INFO (Verde):** Visibilidad de los 12 módulos funcionales.
* **DEBUG (Azul):** Confirmación de inyección de la clase de ámbito (.tpl-{id}).
* **LINK (Amarillo):** Conteo de reglas CSS detectadas y bypass de caché (?v=timestamp).
* **TRACE (Naranja):** Certificación cuantitativa (ej: "4 artistas inyectados").
* **TIME (Púrpura):** Sincronización del Heartbeat y tipografía Geist 900.

## 🎨 II. Estándares Visuales y Multimedia (Cara)

### 5. Sincronización Multimedia 1:1
La playlist de Spotify debe cubrir siempre el 100% de la altura del video (aspecto 16:9), independientemente de la diagramación del template.

### 6. Protocolo de Video YouTube (ADR-005)
Prohibido el uso de `<iframe>` para YouTube en páginas públicas. Se debe extraer el ID y generar una miniatura HD con link externo para evitar el "Error 153" en móviles.

### 7. Silent Fallback y Transparencia Real (ADR-008)
* Toda etiqueta `<img>` dinámica debe incluir `onerror="this.src='path/to/fallback.png';"`.
* No aplicar filtros `invert` o `brightness` en logos sin canal alfa confirmado para evitar "recuadros blancos".

### 8. Tratamiento No-Plano y Geist 900
Las tarjetas de datos técnicos (Dresscode, Aforo) requieren tipografía **Geist 900** y efectos de resplandor (*drop-shadow*) para cumplir el estándar de **$10,000**.

## 📂 III. Gobernanza y Gestión de Silos (Ley de AI-DOS)

### 9. Aislamiento Atómico (Scoped CSS)
Todo el CSS de un template debe estar encapsulado bajo el selector `.tpl-{id}` (ej: `.tpl-f1`). Se prohíbe el uso de variables en `:root` que no tengan prefijo específico del silo.

### 10. Diagramación vía Grid (f1 Standard)
La organización de módulos se gestiona exclusivamente mediante `grid-template-areas` en el CSS, manteniendo el HTML de `evento3.html` inamovible para preservar el Contrato de Datos.

### 11. Integración de Proximidad Multimedia (ADR-010)
Para maximizar la inmersión cinematográfica, el módulo de video debe declararse con `padding-top: 0 !important` para integrarse físicamente con el bloque superior (Countdown/Meta).

### 12. Mandato Maestro de Actualización Documental (Regla v126)
Cada vez que se solicite actualizar los documentos del proyecto, el agente debe:
1. **Revisar exhaustivamente** la versión existente en las fuentes.
2. **Verificar y comparar** para garantizar que no se pierda ninguna información histórica o técnica.
3. **Entregar el texto completo** e íntegro en formato Markdown (.md) listo para copiar y pegar.

## 📐 IV. ACTUALIZACIÓN v2.9: Fidelidad Visual y Armonía Cromática

### 13. Regla #9: Sistema de Armonización Cromática AI-DOS
* **Cálculo HSL Obligatorio:** Todo diseño debe nacer de un cálculo geométrico en el espacio HSL (Hue, Saturation, Lightness). Queda estrictamente prohibido el "hardcoding" de colores HEX que no pertenezcan a una de las 7 armonías matemáticas del sistema.
* **Ley 60-30-10:** La distribución de masas cromáticas es innegociable: 60% Dominante (fondo), 30% Secundario (tarjetas/bloques) y 10% Acento (CTAs/iconos).
* **Blindaje WCAG AA:** El sistema debe garantizar un ratio de contraste mínimo de 4.5:1 para todo texto legible. Si un color de acento no cumple con este ratio, el orquestador debe ajustarlo automáticamente.
* **Bypass de Saturación:** Los fondos deben mantener una saturación baja para generar profundidad, mientras que los elementos de acción deben poseer alta saturación para guiar la vista del usuario.

### 14. Regla #10: Estándar de Calidad Móvil 2026 ($10,000 Quality Standard)
* **Tipografía Dinámica Geist 900:** Uso obligatorio de pesos extremos para establecer una jerarquía visual premium e inmersiva.
* **Experiencia "Afterglow":** Implementación mandatoria de micro-interacciones suaves y transiciones fluidas que emulen el rendimiento del motor Impeller 2.0 a 120 FPS constantes.
* **Diseño Nativo Mobile:** Las interfaces móviles no deben concebirse como un "responsivo reducido", sino diseñadas nativamente para el uso fluido con el pulgar (Thumb-first Mobile UX) y la retención del usuario.

### 15. Regla #11: Lógica de Negocio y Protocolo de "Captura Pura"
* **Eventos Formulario Sin QR:** El sistema debe soportar eventos de tipo "formulario" / captura pura que no generen código QR de acceso.
* **Pantalla Final de Agradecimiento:** En los eventos de captura pura, la pantalla final del asistente mostrará un mensaje de éxito/agradecimiento personalizado en lugar del ticket/código QR tradicional.

### 16. Regla #12: Orquestador de Intención Contextual y Centinela Temporal
* **Flujo Wizard de 4 Pasos:** La creación de eventos debe responder a un flujo orquestado de 4 pasos (Cimiento -> ADN -> Átomos -> Blindaje) que oculte dinámicamente los campos irrelevantes según la categoría del evento (Cine, Fiesta, Campaña).
* **Fecha Centinela (2099-12-31):** En eventos de tipo Campaña, la fecha de realización es opcional. Si el usuario la omite, el orquestador inyectará internamente el centinela `2099-12-31` para desactivar el countdown público de forma automática.
